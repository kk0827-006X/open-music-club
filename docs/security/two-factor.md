# 网站账号两步验证（2FA）

本功能只保护 Open Music Club 账号，与网易云账号无关。不保存明文密码；两步验证本身使用认证器或恢复码，密码找回邮件不能替代已启用的第二因子。认证器与服务端利用共享密钥和时间生成 6 位验证码，每 30 秒更新；允许前后各一个时间窗的时钟偏差，已经使用的时间窗不能重放。

## 配置与使用

1. `.env` 配置 `TOTP_ENCRYPTION_KEY`，值为 32 字节随机数据的标准 Base64。该文件禁止提交，真实密钥不得进入工作树、日志或执行 Agent 上下文。
2. 重启后端，让它加载新的环境变量。生成新环境的密钥：

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
   ```

3. 登录后打开「设置 → 账号与安全 → 管理 2FA」，输入当前密码、扫码或手动输入密钥，再输入验证码确认。
4. 离线保存首次展示的十个恢复码，然后点击「我已保存恢复码」。每个恢复码只能用一次，不会再次返回明文。
5. 退出后重新登录。密码正确后仍停留在登录页；输入新验证码才能进入授权动画。也可以勾选「使用恢复码」。
6. 重启后端再登录，确认绑定仍有效。有效的保持登录 Session 可直接恢复身份，不要求每次打开网页重新输入验证码。
7. 普通用户可输入当前密码和新的验证码关闭 2FA，或重新生成恢复码；管理员禁止自行关闭。

不要反复使用刚刚验证过的验证码；等待认证器更新后再操作。校验失败五次会锁定该账号的安全验证操作 15 分钟，不能靠重新输入密码或换浏览器绕过。待验证登录只有 5 分钟；扫码绑定密钥只有 10 分钟且只属于发起绑定的 Session。公网 IP 对安全修改操作另有限制：每 15 分钟 40 次，使用现有 Redis 限流存储。

## API

所有响应禁止缓存；所有 POST 沿用现有 CSRF 和同源校验。

| 方法 | 地址 | 请求/用途 |
| --- | --- | --- |
| GET | `/api/auth/2fa/status` | 当前账号启用状态、是否必须启用、剩余恢复码数量 |
| POST | `/api/auth/2fa/setup` | `{password}`，返回待绑定密钥、otpauth URL 和二维码 |
| POST | `/api/auth/2fa/confirm` | `{code}`，确认启用并一次性返回恢复码 |
| POST | `/api/auth/2fa/verify` | `{code}`，完成待验证登录 |
| POST | `/api/auth/2fa/recovery` | `{code}`，通过一次性恢复码完成待验证登录 |
| POST | `/api/auth/2fa/recovery-codes/regenerate` | `{password,code}`，废弃旧恢复码并生成新码 |
| POST | `/api/auth/2fa/disable` | `{password,code}`，仅普通用户允许 |

启用 2FA 或公网管理员尚未绑定时，现有 `/api/auth/login` 返回 `requiresTwoFactor: true`；需要绑定时同时返回 `enrollmentRequired: true`，不返回正式身份，也不授予业务权限。管理员绑定期间只能访问自己的绑定接口和退出接口。

## 持久化与安全

- 增量创建 `user_two_factor`、`two_factor_recovery_codes`，不重建现有表。
- 认证器密钥使用 AES-256-GCM 加密，并绑定用户 ID；加密密钥不存数据库。
- 恢复码使用 128 位随机数据，仅保存 SHA-256 哈希及使用时间，不需要保存可解密原文。
- SQLite 事务原子消费验证码/恢复码；同一验证码不能并发重复通过。
- 密码通过、二次验证通过、绑定和安全变更后轮换 Session ID。
- 启用、关闭、重新生成恢复码会更新安全版本，其他旧 Session 与旧待验证流程立即失效。
- 日志仅记录事件、用户 ID、请求 ID，不记录密码、验证码、密钥、恢复码或 Cookie。
- 缺失加密密钥时绑定返回 503 并记录警告；公网管理员仍无法仅凭密码获得正式权限。不得生成临时内存密钥来静默绕过配置。

加密密钥必须与数据库分别安全备份。丢失或随意替换后，已绑定密钥无法解密。管理员认证器与恢复码同时丢失的人工恢复流程当前未实现；禁止临时删除安全表或在公网关闭策略绕过认证。

## 修改密码与忘记密码

设置中的「账号与安全 → 修改密码」要求当前登录会话及原密码。登录页的「忘记密码」向注册邮箱发送一次性链接，打开 `/reset-password#token=...` 后设置新密码，不要求原密码。两个流程使用独立接口与身份凭证，共用密码规则、bcrypt、安全版本和第二因子消费；不会关闭或重新绑定现有认证器。

- 已开启 2FA 的账号，无论修改或找回密码，都必须提供未重放的认证器验证码或一组未使用的恢复码；恢复码只在成功更新密码的同一事务中消费。管理员仍受原强制 2FA 登录策略约束。
- 新密码沿用激活规则：8～72 个可打印半角 ASCII 字符，包含大小写字母、数字和符号，不允许与原密码相同。既有长密码仍按原 bcrypt 行为验证，避免旧账号无法改密。
- 重置链接有效期为15分钟，仅在邮件中携带原始凭证，数据库只存 SHA-256 摘要、用户、安全版本、期限和失败次数。页面首次渲染立即清除 fragment，凭证不进入 URL 查询参数、浏览器存储或日志。刷新后应重新打开邮件，邮件扫描 GET 不消费链接。
- 找回请求对未知、禁用、可用和邮箱超额情况返回同样提示，不等待 SMTP 结果。每邮箱60秒一次、UTC自然日最多五次；请求记录两天后可清理。三个密码接口共用独立 IP 限流：15分钟20次，生产使用现有 Redis Store；第二因子及原密码连续失败还受账号五次失败锁定15分钟约束。单个重置链接第二因子失败五次后失效。
- 新发邮件不主动撤销仍有效的同版本链接；任意一次改密成功，会在同一数据库事务中撤销该用户全部重置链接、旧 Session 和待验证流程，同时清理未完成的 2FA 绑定。其他设备下一次请求立即被拒绝，当前设备返回登录；重置成功不自动登录。
- 邮件仅发送到数据库中的注册邮箱，链接来源固定为 `PUBLIC_ORIGIN`，不信任请求 Host。找回依赖已有 `MAIL_ENABLED`、SMTP、`MAIL_FROM`/管理员邮件配置及 `PUBLIC_ORIGIN`，无需新环境变量；配置缺失统一503。正常改密不依赖邮件可用性。
- 改密成功后尝试发送安全通知。密码邮件在事务提交后通过进程内异步传输发送，有总超时和脱敏日志；不承诺实际送达，不提供持久化重试队列。进程中断可能丢失在途邮件，用户可在限额内重新申请；邮件失败不会回滚已成功更新的密码。邮件服务实际送达需另做真实环境验收。
- 邮箱、认证器及恢复码全部无法使用的人工恢复、修改注册邮箱、私钥恢复不在此功能范围。

| 方法 | 地址 | 请求 |
| --- | --- | --- |
| POST | `/api/auth/password/change` | `{oldPassword,newPassword,code?,recovery?}`，必须已登录 |
| POST | `/api/auth/password/forgot` | `{email}`，公开申请重置邮件 |
| POST | `/api/auth/password/reset` | `{token,newPassword,code?,recovery?}`，仅用于邮件凭证 |

`recovery: true` 表示使用恢复码；否则 `code` 是认证器验证码。全部接口沿用同源、CSRF、防缓存和公网错误脱敏。数据库增量增加 `password_reset_tokens` 与 `password_reset_requests`，不重建用户或音乐表；密码写入、第二因子消费和安全版本更新失败时一起回滚。异步 bcrypt 验证后再次核对安全快照，避免迟到登录或旧安全修改请求在重置后重新获得权限。

## 验证与已知限制

执行 `pnpm test`、`pnpm test:coverage`、`pnpm build:web`。测试账号和加密密钥仅用于临时数据库，不会绑定真实账号。

TOTP 不具备 Passkey 那样的抗钓鱼能力；两步验证不使用邮件或短信，不实现设备列表或跨设备主动推送；密码找回邮件按上节单独验证。

依赖审计仍存在既有风险，包括代理、解析和工具链依赖；历史各轮统计的时间点与范围不同，不能当作当前审计结论。新增的 `otplib` 和 `qrcode` 未出现在当时告警路径中。公网发布前必须用官方源重新审计，修复或明确记录，不得静默忽略，也不得借 2FA 功能升级无关依赖。

真实生产 Redis、HTTPS、Secure Cookie、首次管理员绑定和公网恢复流程尚未验收。公网开放前应完成这些真实环境检查，不能把隔离测试通过当作部署完成。

回退应用代码之前先备份数据库与独立密钥。已有用户启用后，不应直接回退到不检查 2FA 的旧认证代码；生产回退必须保持安全校验或先停止对外服务。新增表可以保留，不会改变音乐业务的数据契约。
